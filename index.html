Ink compiles state and computation together.

Define your data, write the queries you need, and describe how it changes. Ink uses that information to optimise the program.

If an item’s price changes, a total may need updating. A query that only reads item names can keep its result. Ink can use these relationships to avoid repeating work, maintain derived values and choose how data is stored.

You write the behaviour. The compiler works out an implementation.

Optimisation knowledge lives outside the compiler.

Ink draws on a database of reusable algorithms, layouts and transformation laws. Each proposed transformation comes with evidence that the compiler checks before accepting it. Performance measurements help decide whether it is worth using.

That means a new optimisation can improve existing programs when they’re rebuilt. Application code stays the same, and the compiler doesn’t need a dedicated pass for every new idea.

Try it.

Ink is a working prototype with typed state, queries, atomic changes and pure computation. It targets native code, JavaScript and WebAssembly, with GPU support for eligible work.

Optimisation coverage is still growing. The documentation explains what works today, and the benchmarks show where it helps—and where it costs more.
